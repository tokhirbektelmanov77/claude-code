### Что реализовано, но с упрощениями

- Telegram Login Widget для веба не реализован — вход через Telegram работает в Mini App (`/tg`); в вебе Telegram привязывается для уведомлений через deep link.
- Обед/перерывы задаются разрывом между интервалами дня; в редакторе — один перерыв в день (API поддерживает любое число интервалов).
- Переопределение цены/длительности для конкретного мастера есть в БД и API (`BarberService`), но не в интерфейсе.
- Филиалы: CRUD и привязка мастеров; публичная страница показывает адрес бизнеса, фильтра по филиалу нет.
- Фото мастеров/обложка — по URL; загрузки файлов нет.
- Метаданные страниц (`<title>`) только на русском.

### Редизайн «Espresso / Leather»

Тёмная тема стала основной для всех интерфейсов (см. [DESIGN.md](DESIGN.md)). API, бизнес-логика и схема БД не менялись.
Не реализовано из макета: фильтр услуг по категориям («Стрижки / Борода / Комбо») — для него нужно поле категории в БД.
Фото в герое пока временные (фрагменты макета) и требуют замены.

## Не реализовано (следующие шаги)

1. SMS-провайдер (Eskiz / Play Mobile) по интерфейсу `SmsProvider`.
2. Платёжные провайдеры Payme / Click по интерфейсу `PaymentProvider` + webhooks; счета и акты.
3. Telegram Login Widget, webhook-режим бота, кнопки «Подтвердить/Отменить» в уведомлениях.
4. Row Level Security в PostgreSQL как второй уровень изоляции; Redis для rate limit.
5. Загрузка фото (S3-совместимое хранилище), галерея работ.
6. Отзывы и рейтинги (только реальные, после визита).
7. Лист ожидания, повторяющиеся записи, групповые услуги, учёт оплат визитов (тогда — выручка вместо «стоимости по прайсу»).
8. CI/CD, наблюдаемость, нагрузочные тесты, тесты в WebKit и на реальных устройствах.
9. Переход на NestJS 12 / Prisma 7 / TypeScript 7 после стабилизации экосистемы.
