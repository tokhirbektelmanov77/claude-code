# Безопасность

> Документ описывает технические меры MVP. Юридическое соответствие законодательству Республики
> Узбекистан о персональных данных (в т.ч. требования к локализации и согласиям) **не заявляется**
> и требует отдельной проверки юристом.

## Реализовано

| Мера | Как |
| --- | --- |
| Изоляция арендаторов | `BusinessAccessGuard` проверяет активное членство по `:businessId`; каждый запрос дополнительно фильтруется по `businessId`. Тесты: владелец A получает 403 на 6 маршрутах бизнеса B и 404 при подстановке ID из B в свой бизнес |
| RBAC | `OWNER`, `MANAGER`, `BARBER` (через membership), `PLATFORM_ADMIN`. Барбер управляет только своим графиком/записями и видит только своих клиентов. Проверки — на сервере; UI лишь скрывает недоступные разделы |
| Сессии | 32 случайных байта в HttpOnly, SameSite=Lax cookie (Secure в production); в БД — sha256. Отзыв при выходе и удалении аккаунта |
| OTP | 6 цифр из `crypto.randomInt`, хранится HMAC-SHA256 с `OTP_SECRET`, TTL 5 мин, 5 попыток (счётчик увеличивается до сравнения), одноразовый, сравнение `timingSafeEqual`. Лимиты: 3 кода на номер / 10 мин, 5 запросов / 10 мин с IP. Фиксированных кодов нет |
| Dev-режим OTP | `OTP_DEV_MODE` выводит код в ответе и на экране под пометкой «Тестовый режим». API **не запускается** с ним при `NODE_ENV=production`, так же как с `SMS_PROVIDER=console`, `RELAX_RATE_LIMITS` и dev-значением `OTP_SECRET` |
| Telegram | `initData` проверяется по официальному алгоритму (HMAC-SHA256, ключ из `WebAppData` + токен бота), срок `auth_date` ≤ 24 ч; `user.id` с фронтенда без подписи не принимается. Тесты: подделанный id, чужой бот, устаревшие данные → 401 |
| CSRF | SameSite=Lax + отклонение POST/PUT/PATCH/DELETE с чужим `Origin` |
| Валидация | Zod-схемы на каждый body/query; телефоны нормализуются в E.164 (+998); UUID-параметры проверяются |
| Rate limiting | `@nestjs/throttler`: 300/мин глобально, строже на OTP, Telegram и бронирование |
| Перебор ID | UUID v4 для всех сущностей; одинаковый ответ для «нет доступа» и «не существует» на уровне бизнеса |
| Аудит | `audit_logs`: вход, создание/изменение бизнеса, услуг (с ценой до/после), мастеров, графика, команды, экспорт/обезличивание клиента, блокировки, платежи, тарифы |
| Ошибки | Клиенту не отдаются стеки; 5xx пишутся в `error_logs` (без query/body, чтобы не сохранять ПДн) |
| Заголовки | Helmet в API; `nosniff`, `Referrer-Policy`, `Permissions-Policy` в web; `x-powered-by` отключён |
| Секреты | Только через переменные окружения; `.env` в `.gitignore`; в репозитории лишь `.env.example` |
| Целостность записи | Транзакция с `FOR UPDATE` + exclusion constraint + уникальный idempotency key |

## Персональные данные

- **Минимизация**: клиент сообщает только имя и телефон (телефон подтверждён OTP); в Telegram-входе — имя и id. Барбер видит только своих клиентов. Логи не содержат тел запросов.
- **Согласие**: обязательный чекбокс при записи (`customers.consent_at`), отметка при регистрации (`users.privacy_accepted_at`).
- **Экспорт**: `GET /me/export` (клиент), `GET /businesses/:id/customers/:cid/export` (владелец).
- **Удаление**: `DELETE /me` — будущие записи отменяются, имя/телефон/Telegram удаляются, сессии отзываются; `DELETE /businesses/:id/customers/:cid` — обезличивание клиента. История визитов остаётся без ПДн.
- Демо-данные полностью вымышлены (номера `+99890000000X`, `+9989100000XX`).

## Резервное копирование

`scripts/backup-db.sh` — `pg_dump -Fc` с ротацией 14 копий (проверено: дамп читается `pg_restore`). В production: запуск по расписанию, шифрование, хранение вне сервера БД, регулярная проверка восстановления.

## Известные ограничения

- Нет Row Level Security в PostgreSQL (изоляция — на уровне приложения).
- Нет 2FA для PLATFORM_ADMIN и ограничения входа в админку по IP.
- Rate limit хранится в памяти процесса — при нескольких инстансах API нужен общий storage (Redis).
- Нет антибот-защиты (captcha) на OTP; SMS-флуд ограничен только лимитами.
- CSP не настроена (Next.js inline-скрипты требуют nonce-конфигурации).
- Токен бота и OTP_SECRET не ротируются автоматически.
- Внешний аудит безопасности / пентест не проводился.
